# Localisation

Issue #32. The IDE is written in English and translated through KDE's catalogs (gettext `.mo` files, domain
`tinox-ide`). German is included. The language follows the user's locale (`LANGUAGE`, `LC_MESSAGES`, the KDE
language settings); without a catalog for it the English text is shown.

## Why it works at the bridge

Tinox has no message API of its own yet (subnix-work/tinox#588), and KDE's `i18n()` only works on strings
the C++ compiler sees. So Tinox keeps writing plain English literals, and **the bridge translates what it is
given** (`bridge/src/i18n.h`, `tkde::tr`): the text and tool tips of actions, menu and section titles, labels,
buttons, check boxes, placeholders, window, dock and tab titles, combo box items, model column headers,
accessible names, status bar messages, dialog titles, texts and buttons, and notifications. Text the user types
(line edits, logs) and tree rows are data and are never looked up. A string no catalog contains, a file name
for instance, passes through unchanged.

For messages the IDE puts together at run time there is `Tr` (`src/tinox/ide/app/Tr.tnx`), which asks the bridge
(`i18n.translate`) and falls back to the English text without it, so the tests against the mock still read English:

```tinox
store.set("status.message", Tr::f("Opened %1", [title]))                       // %1, %2 … are filled in after the lookup
message = Tr::n("%1 test found", "%1 tests found", count, [])                   // plural forms follow the language
label = Tr::c("menu", "Open")                                                   // a context, for words with two meanings
```

Never build a sentence by concatenation (`"Opened " + title`): a translator cannot move the title. Use
`Tr::f` with placeholders. Keep the mnemonic (`&`) in menu texts; the translator chooses a letter that is free in
that menu.

## The catalogs

```sh
make i18n            # scripts/i18n-extract.py --update: rescan the sources, merge into po/*/tinox-ide.po
```

* `po/tinox-ide.pot` is generated from the sources by `scripts/i18n-extract.py` (the arguments of the UI
  builders, `Tr::*` and the bridge's `i18n*` calls; comments are skipped). `scripts/test-i18n.sh` fails when it is
  stale.
* `po/<language>/tinox-ide.po` are the translations. The build installs them with `ki18n_install` as
  `share/locale/<language>/LC_MESSAGES/tinox-ide.mo` (needs `msgfmt`, see [development.md](development.md)).
* A new language: `msginit -i po/tinox-ide.pot -l fr -o po/fr/tinox-ide.po`, translate, `make bridge`.
* A string that is not found by the extractor (it is built from parts, or comes from a variable) has to be given as
  a literal or through `Tr`; the extractor lists the builders it knows in `TINOX_PATTERNS`.

## Try it

```sh
cmake --install bridge/build --prefix /tmp/tinox-ide-prefix
LANGUAGE=de XDG_DATA_DIRS=/tmp/tinox-ide-prefix/share:/usr/share make run
```

## Limits

* Messages that still concatenate (most log lines in the Build and Debug Console output, parts of error texts that
  come from the compiler or the language server) stay English; so do the compiler's own messages.
* Plural and word order work only where `Tr::n` / `Tr::f` is used. The most visible status and dialog messages were
  converted; the rest follows as they are touched.
* Plural forms come from the catalog's `Plural-Forms` header, so any language works; the fallback without the bridge
  (the tests against the mock) uses the English rule.
* KDE's own widgets (file dialogs, the editor's search bar, standard actions) are translated by KDE, in the
  user's language, independent of this catalog.
